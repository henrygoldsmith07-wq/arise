# ADR 0013 — PWA-first; native wrapper is an optional shell, not a rewrite

Date: 2026-09-04 · Status: accepted

## Context

The app already behaved like an app (offline-first SW, wake lock, safe-area
bottom insets, deferred SW updates) but had gaps that surface only on real
devices: no install onboarding (iOS users had no guidance; Chromium users got
Chrome's mini-infobar instead of a controlled prompt), no home-screen
shortcuts, no top safe-area handling in standalone, raw `navigator.vibrate`
calls scattered across components, no Web Share integration, no offline
status signal, and no iOS splash images.

## Decision

1. **PWA-first.** Everything user-facing ships in the web app: platform-aware
   install card (one-tap prompt on Chromium, manual Share → Add to Home Screen
   on iOS, honest copy in in-app browsers; hidden entirely when standalone),
   manifest shortcuts (`?shortcut=start-workout` / `quick-log`, consumed and
   scrubbed on landing), per-device iOS splash PNGs (generated, both colour
   schemes), `body.standalone` top safe-area padding, an offline banner that
   probes rather than trusting `navigator.onLine`, and native share with a
   clipboard fallback.
2. **Haptics become a module, not a call site detail.** `haptics.js` names the
   patterns (tap, set-complete, rest-complete, failed-set, guided steps),
   routes them through a pure event→pattern map, honours a user preference
   (`preferences.haptics`, default on), and reports honestly that iOS Safari
   has no Vibration API. All raw `navigator.vibrate` call sites are gone.
3. **Notifications are NOT added.** They would be the first feature that
   proactively interrupts the user, which conflicts with the consent posture
   (ADR 0011). If ever added: opt-in only.
4. **Capacitor is a documented option, not a dependency.** `docs/capacitor-wrapper.md`
   describes wrapping the same build for store distribution with zero new web
   dependencies; widgets/Live Activities/background-audio notes are included
   as future work *inside the wrapper*, where they belong.
5. **PWA e2e runs against production.** The SW is PROD-only, so `pwa.spec.js`
   runs under its own Playwright config against `vite preview`
   (`npm run e2e:pwa`) and is ignored by the dev-server suite; CI runs both.
   The offline test proves the shell boots from the SW cache with the network
   severed.

## Consequences

- Install UX is now under our control (and testable), not the browser's.
- Shortcut URLs are part of the app contract; removing a manifest shortcut
  would strand installed users until the URL guard no-ops (it does).
- A small maintenance cost: splash PNG sizes are device-specific; the matrix
  doc lists the exact devices to re-verify when adding sizes.
- The real-device matrix (docs/device-test-matrix.md) is documentation, not
  automation — physical-device claims in release notes must be re-verified
  per release.
